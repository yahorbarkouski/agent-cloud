# Image release design comparison

Score each candidate0–5 per criterion, total30. Read each complete candidate and the shared task/grounding. Recommend the smallest coherent shape that reaches the whole publication boundary. Identify concrete omissions and required corrections, not prose preferences.

1. Full public input provenance and an authenticated release connect exact installer/tool/service inputs, sanitation receipt, snapshot and consumed GuestImage without self-referential hashing.
2. Platform ownership and persisted intent cover builder, verification VM, IP, management key/firewall and snapshot; unknown creates and duplicate observations cannot cause blind resubmission or adoption.
3. Gross currency/price ceilings, bounded storage and deadlines cover all paid resources; failed/expired builds remain cleanable and retained snapshots have an explicit policy.
4. Builder and verification access use isolated keys and pinned identity with a defensible initial trust source; no provider/CA/fleet secret reaches a guest or public journal.
5. State and module design use discriminated unions and short call chains, avoid fake customer allocations and arbitrary workflow frameworks, and integrate the existing bootstrap/runtime path.
6. Concrete recovery and verification cover interrupted installation, sanitation/access loss, source shutdown, uncertain snapshot creation, source/snapshot deletion and real provider boot without overclaiming local proof.

The parent independently reviews candidates while a different-model judge scores them. No candidate implementation is accepted just because its design wins.
