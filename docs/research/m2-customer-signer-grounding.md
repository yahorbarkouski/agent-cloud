# Customer certificate implementation notes

The selected access design keeps signing in the control worker. Existing guest signer code uses pinned Step0.30.6, a private workspace, isolated process environment and20-second subprocess limits. `step ssh inspect` checks certificate structure and policy. The authenticated CA response and native OpenSSH provide the existing trust boundary; inspection alone is not signature verification.

The current template gives every user certificate a forced command and no extensions. Customer access needs a separate branch in that template and a separate inspector. Existing host/probe/runtime behavior must stay intact. Reusing the operator provisioner avoids another private identity to distribute; the customer API never receives provisioner material.

A bounded native `step ca token --ssh --set-file` probe confirmed custom claims under `.Token.user.agentCloudAccess`. The private output retained only claim names and dummy public data; it requested no SSH certificate. Evidence is root `.local/customer-token-claim-shape.json`.

The signer will derive a complete claim from the immutable session and a current database authority observation. It includes the audit key ID, one allocation principal, exact public-key wire bytes, gateway source CIDRs and absolute validity. The CA template must compare the supplied key with the signed wire bytes and emit only signed metadata, `source-address` and `permit-pty`. Missing or altered claims cannot acquire customer privileges. The pinned crypto library exposes the request's SSH public key to templates; its public `Marshal` method was verified natively: a valid certificate issues and a substituted public key is rejected with HTTP400.

Generate one token into bounded process stdout and keep it in memory. Submit one HTTPS request directly to `/ssh/sign` with explicit CA trust, no redirects, bounded response size and the caller's abort deadline. This keeps the OTT out of command arguments. A lost response cannot trigger another token or signing POST. The session's persisted attempt owns uncertainty.

Round timestamps down to whole seconds. Begin validity60seconds before the current database observation, and end by the earliest of observation+240seconds, original hard deadline and current ancestry expiry. Reject if no positive whole-second lifetime remains. Total certificate lifetime stays at most5minutes while meeting the configured1-minute CA minimum. The customer inspector must compare the exact absolute bounds; the existing host-clock-relative validity helper is insufficient.

Next verification uses the native CA and OpenSSH with disposable local resources. Cover signed/unsigned/missing/altered claims, key substitution, branch separation, sources, exact permissions, near-expiry validity, cancellation/lost responses and workspace cleanup. No access endpoint, worker issuance, gateway or access-capable image is implemented by these notes.

Both existing and fresh setup now omit the logger, and native smoke scans actual output without printing it. Source: [pinned CA middleware construction](https://raw.githubusercontent.com/smallstep/certificates/v0.30.2/ca/ca.go).
